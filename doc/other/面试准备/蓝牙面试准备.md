## 二、项目故事：BLE 蓝牙通信项目

### 项目背景

在智能硬件 / 穿戴设备项目中，基于 BLE（低功耗蓝牙）完成 Android 端与 Flutter 跨端的双端蓝牙通信能力，涵盖扫描、连接、配对、GATT 服务与特征读写、Notify/Indicate 订阅、MTU 协商、OTA 固件升级等完整链路。

### 核心职责与技术亮点

#### 1. 蓝牙连接链路设计

- **完整连接流程**：权限检查（Android 12+ `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT`）→ 适配器状态检查 → 带过滤条件的扫描（`ScanFilter` by Service UUID）→ `connectGatt(autoConnect=false)` 直连 → `discoverServices()` → `requestMtu(512)` → 写 CCCD 开启 Notify → 协议握手 → 进入数据通信。
- **连接参数协商**：连接建立后通过 `requestConnectionPriority(CONNECTION_PRIORITY_HIGH)` 降低 Connection Interval 至 7.5~15ms，满足实时数据传输需求；数据同步完成后切回 `BALANCED` 模式降低功耗。
- **MTU 协商**：默认 MTU 为 23 字节（有效载荷 20 字节），通过 `requestMtu(512)` 协商至 512 字节，减少分包数量，提升大数据量传输效率。协商失败时回退到默认 MTU 并切换分包策略。

#### 2. 并发指令队列

- **问题**：Android BLE 协议栈要求同一时刻只能有一个 GATT 操作（Write / Read / DiscoverServices 等），多业务并发时会出现 `GATT_BUSY` 导致操作丢失。
- **方案**：设计基于 `LinkedBlockingQueue` 的串行指令队列，所有 GATT 操作统一入队，前一个操作的 `onXxx` 回调触发后自动出队执行下一个。
  - 支持超时机制：每条指令设置超时时间（默认 5s），超时后回调失败并自动执行下一条，避免队列阻塞。
  - 支持优先级：OTA 数据包的 ACK 响应为高优先级，插入队首；心跳包为低优先级。
  - 线程安全：队列操作在单线程 Executor 中执行，回调通过 `Handler(Looper.getMainLooper())` 分发到主线程。

#### 3. 分包粘包协议

- **分包策略**：应用层数据超过 MTU 有效载荷时，按 `MTU - 3` 字节切分。每个分包携带：帧头（0xAA）+ 包序号 + 总包数 + 数据长度 + 数据 + CRC16 校验。
- **粘包处理**：接收端维护 `ByteArrayOutputStream` 缓冲区，按帧头定位包边界，校验 CRC16 后按包序号重组。超时未收齐则丢弃整帧并请求重传。
- **流控**：发送端采用「发送-确认」机制，每发一批（如 10 包）等待接收端 ACK 后再发下一批，避免 BLE 栈缓冲区溢出。

#### 4. 断线重连策略

- **断线检测**：`onConnectionStateChange` 回调中 `newState == STATE_DISCONNECTED` 时触发重连流程。区分主动断开（用户操作）与异常断开（信号弱 / 设备端异常）。
- **指数退避重连**：重连间隔为 1s → 2s → 4s → 8s → 16s，最大重试 5 次。超过最大次数后通知上层并进入扫描重连模式。
- **后台保活**：BLE 连接管理封装在 `ForegroundService` 中，确保 App 进入后台后连接不被系统回收。结合 `autoConnect=true` 进行系统级后台重连兜底。

#### 5. OTA 固件升级

- **流程**：进入 DFU 模式（发送特定指令）→ 设备重启进入 Bootloader → 分包传输固件（每包 244 字节，批次 20 包 + ACK）→ 传输完成发送校验指令 → 设备校验固件完整性 → 重启进入新固件。
- **断点续传**：记录已传输的包序号，中断后从断点继续，无需重传全部固件。
- **进度展示**：Flutter 端通过 EventChannel 实时接收传输进度，UI 层展示进度条与状态文案。
- **异常处理**：传输失败自动重试 3 次；校验失败回滚到旧固件并上报错误。

#### 6. Flutter 跨端封装

- **Platform Channel 对接**：原生端（Kotlin）封装 BLE 核心能力，通过 MethodChannel 暴露扫描 / 连接 / 读写 / OTA 等接口，通过 EventChannel 推送连接状态变化与 Notify 数据流。
- **flutter_blue_plus 集成**：基于 `flutter_blue_plus` 封装统一的 `BleManager`，屏蔽 iOS/Android 差异（如 iOS 无需处理蓝牙权限弹窗时机、Android 需动态申请位置权限）。
- **状态管理**：使用 BLoC / Riverpod 管理蓝牙连接状态（Disconnected → Scanning → Connecting → Connected → Ready），UI 层响应式展示。

#### 7. 功耗与性能优化

- **扫描优化**：使用 `ScanSettings.SCAN_MODE_LOW_LATENCY` 仅在前台使用，后台切换为 `SCAN_MODE_LOW_POWER`；设置扫描超时（15s）自动停止。
- **连接优化**：直连模式（`autoConnect=false`）减少首次连接时延（从平均 6s 降至 2s）；连接后协商高优先级参数，数据同步完成后降级。
- **弱网优化**：RSSI 实时监测，信号低于阈值（-85dBm）时主动降低数据发送频率并触发预警。

### 项目成果

- 完成扫描 → 连接 → 通信 → OTA 全链路闭环，支持 3+ 品类智能设备上线。
- 并发指令队列 + 分包协议使数据丢包率从 5% 降至 0.1% 以下。
- 断线重连策略使异常断连后的自动恢复成功率达到 95%+。
- OTA 传输 512KB 固件耗时从 120s 优化至 45s（MTU 协商 + 批次流控）。
- Flutter 跨端方案实现 iOS/Android 双端代码复用率 90%+。
